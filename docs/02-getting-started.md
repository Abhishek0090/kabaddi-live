# 02 Getting started

Run modes, environment variables and scripts. Full Supabase and Vercel steps are in the [project README](../README.md).

## Run modes

| Mode | Set in `.env` or `.env.local` | Data | Use it for |
| --- | --- | --- | --- |
| Mock | `NEXT_PUBLIC_MOCK=true` | In memory, resets on restart | Trying the app, UI work, demos |
| Supabase | `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` | Your Supabase project | Real matches |
| Neither | nothing | none | The home page shows setup instructions |

If both are set, mock mode wins. Restart `npm run dev` after changing env files.

## Environment variables

| Variable | Where it comes from | Notes |
| --- | --- | --- |
| `SUPABASE_URL` | Supabase: Project Settings > Data API > Project URL | Sent to the browser (see below) |
| `SUPABASE_PUBLISHABLE_KEY` | Supabase: Project Settings > API Keys > Publishable key (`sb_publishable_...`) | Sent to the browser; RLS protects the data. Never use the secret key here |
| `NEXT_PUBLIC_MOCK` | You | `true` turns on mock mode. Never on a real deployment |

GitHub Actions needs the same two names as repository secrets for the keep-alive job.

### Why the Supabase values reach the browser

The browser talks to Supabase directly for live updates and for saving taps, so it needs the URL and the publishable key. The names have no `NEXT_PUBLIC_` prefix; instead the `env` block in [next.config.ts](../next.config.ts) copies them into the browser bundle at build time. The effect is the same as the prefix, and it avoids Vercel's warning.

This is safe: the publishable key only allows what the RLS policies in `supabase/schema.sql` allow. The key that must stay private is the Supabase secret key, and this app never uses it. Never add it to `next.config.ts`.

Because the values are copied at build time, change them in Vercel's project settings and redeploy.

To add another browser-visible variable, either list it in that `env` block or give it the `NEXT_PUBLIC_` prefix.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Development server on port 3000 |
| `npm run build` | Production build |
| `npm start` | Serve the production build |
| `npm run lint` | ESLint over the whole project |
| `npm run typecheck` | Generates Next route types, then runs `tsc --noEmit` |
| `npm test` | Vitest suites in `tests/` |
| `npm run share` | Writes setup and update scripts to `kabaddi-share/` (see [12 Sharing](12-sharing.md)) |

`typecheck` runs `next typegen` first because types such as `PageProps` and `LayoutProps` are generated by Next.js into `.next/types`.

## Stack

| Part | Version | Notes |
| --- | --- | --- |
| Next.js | 16.4 | App Router, `src/` layout, `proxy.ts` instead of `middleware.ts` |
| React | 19.3 | |

No other runtime libraries are used. Add one only after agreeing it with the project owner.

## Next.js 16 notes

- `params` and `searchParams` are promises: `const { id } = await params`.
- `cookies()` and `headers()` are async.
- The route guard file is `src/proxy.ts` (`middleware.ts` is deprecated).
- `next lint` no longer exists; `npm run lint` calls ESLint directly.
- The bundled docs in `node_modules/next/dist/docs/` match the installed version. Check them before using an API you are unsure of.
