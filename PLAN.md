## 3. Data model

### 3.1 TypeScript (lib/kabaddi.types.ts)

```ts
type Team = "A" | "B";
type Phase = "pre" | "play" | "halftime" | "fulltime";

interface Settings {
  playersOnMat: number;      // 7
  halves: number;            // 2
  halfMs: number;            // 20 * 60_000
  raidMs: number;            // 30_000
  timeoutsPerHalf: number;   // 2
  timeoutMs: number;         // 30_000
  allOutBonus: number;       // 2
}

interface Clock { runningSince: number | null; remainingMs: number } // epoch ms, server time

interface TeamState {
  name: string;
  score: number;
  onMat: number;
  outQueue: number[];        // see Q1
  timeoutsLeft: number;
  emptyRaids: number;        // consecutive
}

interface MatchState {
  settings: Settings;
  teams: Record<Team, TeamState>;
  half: 1 | 2;
  phase: Phase;
  matchClock: Clock;
  raidClock: Clock | null;   // null = no raid in progress
  raidingTeam: Team | null;  // null until the scorer picks the first raider
  firstRaiderHalf1: Team | null;
  doOrDie: boolean;          // derived from raidingTeam.emptyRaids >= 2, stored for display
  timeout: { team: Team; endsAt: number; matchRemainingMs: number } | null;
  feed: FeedItem[];          // last 20, newest first; full log lives in match_events
  lastSeq: number;
}

type MatchEvent =
  | { type: "SET_RAIDING_TEAM"; team: Team; at: number }   // see Q5
  | { type: "START_CLOCK" | "PAUSE_CLOCK" | "START_RAID" | "STOP_RAID"
      | "BONUS" | "EMPTY_RAID" | "TACKLE" | "RAID_TIMEOUT"
      | "END_HALF" | "START_SECOND_HALF" | "RESUME"; at: number }
  | { type: "TOUCH"; n: 1|2|3|4|5|6|7; at: number }
  | { type: "TIMEOUT"; team: Team; at: number };
```

Every event carries `at` (server-adjusted epoch ms of the tap). That keeps `applyEvent` pure and makes replay exact.

`applyEvent` returns `{ ok: true, state } | { ok: false, error: string }`. The brief's signature returns `MatchState`, but rejected events need a message for the inline error. I'd rather return a result than throw. Tell me if you want throwing instead.

### 3.2 Engine order of operations for a scoring event

1. Reject if phase is not `play`, a timeout is active, or (for raid outcomes) no raid is running.
2. Apply points, outs, and revivals.
3. All-out check for both teams: if `onMat === 0`, the other team gets `allOutBonus`, this team resets to `playersOnMat` and its `outQueue` is cleared.
4. Update the empty-raid counters, switch the raiding team, clear the raid clock, recompute `doOrDie`.
5. Push a feed item.

Edge rules I will apply unless you say otherwise:

- TOUCH with n greater than the defenders on the mat is rejected.
- Revival never takes `onMat` above `playersOnMat`.
- BONUS is allowed only once per raid.
- Raider out (tackle, raid timeout, do-or-die empty) moves one raiding player to that team's `outQueue`.

### 3.3 Database (supabase/schema.sql)

- `matches`: as in the brief, plus `scheduled_at timestamptz` (the create form asks for date/time but the brief's schema has no column for it) and `last_seq int not null default 0`.
- `status` is set inside the RPCs from `p_state->>'phase'`: `pre` = `scheduled`, `play`/`halftime` = `live`, `fulltime` = `finished`. The client never writes it directly.
- `match_events`: as in the brief, with `unique (match_id, seq)`.
- RLS as in the brief. INSERT on `matches` is allowed when `scorer_id = auth.uid()` (needed for the create form). Sign-ups are disabled in the Auth settings. README covers this.
- `record_event(p_match, p_seq, p_type, p_payload, p_state)`: SECURITY INVOKER. Locks the match row with `FOR UPDATE`. If `p_seq = last_seq + 1`, it inserts and updates. If `p_seq <= last_seq` and the stored event at that seq has the same type and payload, it returns `'duplicate'` and the client treats it as synced. This covers a retry after a lost response. Anything else raises an error.
- `undo_last_event(p_match, p_seq, p_state)`: **adds `p_seq`**, which is not in the brief. Without it, a retried undo whose first response was lost would delete two events. It deletes only if `p_seq = last_seq`. If that seq is already gone, it returns `'duplicate'`.
- `server_now()`: returns `now()` for clock offset (4.2). Not in the brief. It is small and needed for the clocks to agree between devices.
- `alter publication supabase_realtime add table matches;`

## 4. Key mechanisms

### 4.1 Optimistic scoring and offline queue

The scorer page loads the full event log. Each tap does this:

1. Build the event with `at = serverNow()`.
2. Run `applyEvent`. If it is rejected, show an inline message and stop.
3. Update local state and push `{ kind: "event", seq, type, payload, state }` to the queue in localStorage.
4. Flush the queue in order: one RPC at a time, stopping at the first network failure. Retry every 3 s and on the `online` event.

Undo replays `log.slice(0, -1)` from the initial state. If the last event is still unsynced, undo drops it from the queue and sends nothing. Otherwise it queues `{ kind: "undo", seq, state }`. Badge: "Not synced (n pending)".

### 4.2 Clocks

State stores `{ runningSince, remainingMs }` only. Display time is `remainingMs - (serverNow() - runningSince)`, clamped at 0. `serverNow()` is `Date.now() + offset`. The offset comes from `server_now()` with an RTT/2 correction on load and on reconnect. Without this, a tablet whose clock is 20 s off would make every viewer's clock wrong by 20 s.

Auto events: the scorer page watches the clocks and sends `END_HALF` or `RAID_TIMEOUT` with `at` set to the exact expiry time, not the detection time. Timeout expiry works the same way (Q3).

Limitation: auto events need the scorer page open. If the tablet sleeps, nothing is sent. To cover that, public pages render "Half time" as soon as their computed match clock reaches 0, even before the event arrives. That is display only and does not change state.

### 4.3 Realtime (lib/useLiveMatch.ts)

The hook takes the SSR row as initial data and subscribes to `postgres_changes` UPDATE on `matches` with `id=eq.{id}`. It refetches the row on `SUBSCRIBED` after a drop, on `visibilitychange`/`focus`, and on `online`. Status is `"live" | "reconnecting"` and drives `ConnectionBadge`.

### 4.4 Auth

`@supabase/ssr` cookie sessions. `proxy.ts` refreshes the session and redirects unauthenticated `/scorer/*` requests to `/login?next=...`. The ownership check (`scorer_id = user.id`) runs in `scorer/[id]/page.tsx` and returns 404 for other users. RLS enforces it again on writes.

### 4.5 Big scoreboard (/match/[id])

The scoreboard fills the screen so it reads from across a ground or on a TV/projector:

- Scores are the largest element. Font size uses viewport units with `clamp()`: about 30vw per score in phone portrait, about 18vh on landscape and TV. The two teams sit side by side in every orientation.
- Team names, match clock, and raid clock come next in size. Mat dots are large (about 6vw). Do-or-die and the banners stay readable at a distance.
- Last 5 events and timeouts left sit below the fold on phones and in a side strip on landscape/TV.
- Tabular numerals, so digits don't shift as the clock ticks. High contrast in both dark and light mode.
- The overlay (`/overlay/[id]`) stays compact. A big overlay would cover the stream.

### 4.6 PWA

- **Installable:** `app/manifest.ts` with name, `display: "standalone"`, theme colors, `start_url: "/"`, and 192/512 PNG icons plus a maskable icon, all generated by `next/og` (built into Next, no new dependency). An Apple touch icon is included for iOS.
- **Service worker (`public/sw.js`), registered in production only:**
  - `/_next/static/*` and icons: cache-first (file names are hashed, so this is safe).
  - Page navigations: network-first, falling back to the cached copy, then `offline.html`. If the tablet reloads `/scorer/[id]` with no signal, the control panel still opens and the offline queue keeps working.
  - Supabase API and Realtime requests are never cached or intercepted. Score writes stay in the localStorage queue from 4.1, not in the service worker.
  - Bumping a version constant clears old caches on deploy.
- **Sign-out clears the page cache**, so a shared device doesn't keep a scorer's cached panel.
- I'm not adding push notifications or background sync. They aren't needed, and iOS Safari support for them is limited.

## 6. Free-tier limits you should know

- **Supabase Realtime: about 200 concurrent connections on Free** (third-party sources; not on Supabase's pricing page). Each open `/match` or `/overlay` tab counts as one. A popular match will hit this. Viewers past the cap get no live updates. The refetch-on-focus still gives them fresh data when they come back to the tab. I am not building a polling fallback unless you ask.
- **2M Realtime messages/month.** One update multiplied by each connected viewer counts. 200 viewers x 500 events per match = 100k per match. That's fine for a club.
- **Supabase pauses after 7 days idle.** The keep-alive cron prevents this. But **GitHub disables scheduled workflows in public repos after 60 days without repository activity**. The README will say so. The fix is a commit or re-enabling the workflow.
- **Vercel Hobby is for non-commercial use only.** If matches carry sponsors or paid streams, that breaks Hobby's terms.

## 8. Decisions and open questions

### Decided

- **Q1 Players:** counts only. `outQueue` holds anonymous slot numbers so revival order is kept and tested.
- **Q2 Revival:** RAID_TIMEOUT and an empty do-or-die raid both work like TACKLE: defending team +1 and revives 1. No super tackle on these.
- **Q3 Timeout end:** the timeout clears automatically (the scorer page sends RESUME at `endsAt`). Clocks stay paused until the scorer taps Start clock or Start raid.
- **Q6 Env var:** renamed on 2026-10-27 to `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` (no `NEXT_PUBLIC_` prefix). `next.config.ts` `env` passes them to the browser. Same names as the GitHub secrets.
- **Added after the brief:** big scoreboard (4.5) and PWA (4.6).
- **Admins and rooms (added 2026-10-27):** anyone can register at `/register` and becomes an admin. Every match is a room owned by the admin who created it; only that admin can score it. Sign-ups stay enabled in Supabase (this replaces "disable sign-ups" from 3.3). URLs keep the brief's `/scorer` paths; the UI says "Admin" and "rooms". Email confirmation is optional (README section 1).
- **Mock mode (added 2026-10-27):** `NEXT_PUBLIC_MOCK=true` runs the app on an in-memory store (`src/lib/mock/`) with a self-playing demo match, a demo admin, and 1-second polling instead of Realtime. Home page redesigned with a hero and a live featured match.
- **Share scripts (phase 8):** standalone `npm run share` in `scripts/share.mjs`, runtime in `scripts/share-runtime.mjs`.

### Still open (the recommended option is used unless you say otherwise)

**Q4. Do-or-die counter reset.** "Any point resets the count." Recommended: any non-empty raid by that team resets it, including one where the raider was tackled. That is the PKL rule. The other reading (only reset when that team scores) would let a team stay in do-or-die after being tackled.

**Q5. First raider.** The scorer picks the raiding team before the first raid (toss result) with `SET_RAIDING_TEAM`. That pick is recorded as `firstRaiderHalf1`. Is the selector allowed to change the raiding team mid-half (to fix a mistake), or only before the first raid? Recommended: allowed any time no raid is running, logged as an event so it replays.

**Q6. Env var name.** Keep `NEXT_PUBLIC_SUPABASE_ANON_KEY` as the brief says (holding the new publishable key value), or rename it to `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` to match Supabase's current docs? Recommended: rename. The same applies to the GitHub secret.

**Q7. Deviations to approve:** `scheduled_at` and `last_seq` columns, the `p_seq` parameter on `undo_last_event`, the `server_now()` RPC, and `applyEvent` returning a result object instead of a bare state.
